# Fastlane / Triple-T Play Store Metadata

This directory holds the version-controlled Google Play Store listing copy for
OpenTransition. Files here mirror the structure consumed by the
[Triple-T `gradle-play-publisher`](https://github.com/Triple-T/gradle-play-publisher)
and [Fastlane `supply`](https://docs.fastlane.tools/actions/supply/) tooling.

## Layout

```
fastlane/metadata/android/
└── en-US/
    ├── title.txt              # ≤ 30 chars
    ├── short_description.txt  # ≤ 80 chars
    ├── full_description.txt   # ≤ 4000 chars
    ├── marketing_url.txt
    └── changelogs/
        └── <versionCode>.txt  # ≤ 500 chars per release
```

Add a new `changelogs/<versionCode>.txt` file for each release. The mobile app's
`versionCode` is generated by `getAppVersionCode()` in the root `build.gradle`.

## Why this exists

Per the audit (`audit-report/15-release-and-distribution.md` §4), Play Store
listing copy and Data Safety declarations previously lived only in the Play
Console — a bus-factor risk and unauditable from source control. Storing them
here lets PRs review changes to marketing claims and privacy disclosures.

## What is intentionally NOT here

- **Real Privacy Policy** — must be hosted at a stable public URL. The `privacy_policy_url.txt`
  file should be added once that URL exists.
- **Data Safety form contents** — Google does not currently support uploading these
  via the Play Developer API. They must be entered manually in the Play Console.
- **Feature graphic, screenshots, app icon** — large binaries; managed in the Play
  Console directly. Source screenshots already live in `screenshots/` at the repo root.
